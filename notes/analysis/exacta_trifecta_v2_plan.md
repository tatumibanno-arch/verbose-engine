# 2連単 v2: 厳密な予想オッズでの再点検（事前の計画）

2026-11-03 作成。**新しいオッズで評価する前に**、候補と評価の手順をここに固定する。
中身（候補・期間の切り方・選び方・合格ライン）を評価の後に変えたら、それは別の新しい計画として書き足し、試した数に足す。

前回までの経緯は `notes/analysis/multi_bet.md`（特に 2026-11-03 追記）。2連単 EV最大1点（P2≥5%・EV≥1.2）は、
q̂ を過去のオッズだけで学習した厳密版の 2026-01〜10 で 1.011 [0.89〜1.14]・勝ち月 6/10＝損益分岐ちょうど。
厳密に見られる月が10か月しかなかったのが弱点。いま 2023-11〜2025-10 の3連単・単勝の締切オッズを取り込み中
（その後に直前情報、2連単の締切オッズ）。オッズが増えると、厳密に見られる月が過去へ延びる。

## 何を変えたか（コード: scripts/analysis/multi_bet.py, multi_bet_eval.py, nirensho_today.py）

1. **オッズのある月を DB から決める**（`multi_bet.py prep` → `mb/odds_months.json`）。
   月 m を「オッズのある月」とするのは、結果のあるレースの **95%以上**（`ODDS_COMPLETE`）に全通りのオッズ
   （3連単 120・2連単 30・単勝 6）が揃ったときだけ。取り込み途中の月は自動で外れ、揃えば次の prep で入る。
   `multi_bet.py coverage` で月ごとの揃い具合だけ見られる（重い処理なし）。
2. **予想オッズ q̂ をウォークフォワード（拡大窓）で毎月学習**（`oddswf`）。月 m の q̂ は「m より前のオッズ月すべて」で学習。
   前のオッズ月が `MIN_PRIOR_ODDS`=2 か月以上ある月を「厳密」とする。学習レースは最大 `ODDS_MAX_TRAIN_RACES`=40,000
   （超えたら一様に間引く。メモリ対策）。月ごとの結果は `mb/qwf/q3_YYYY-MM.npz` に置き、学習月が同じなら作り直さない。
   - 厳密でない月（最初のオッズ月より前など）にも、最初の2か月のオッズで学習した q̂ を入れる（その月自身は学習から除く）。
     これは厳密な月 m の g2+ の**学習行**を埋めるためだけ。そのとき使うオッズは全部 m より前なので、m の買い目は
     m より前の情報だけで決まる。
   - 旧版（LOMO: 未来の月のオッズも学習に入る）は使わない。
3. **2連単の締切オッズがあれば q̂2 を直接学習**（`odds2wf`）。`odds` の `ticket_type='nirensho'`（scrape_web の odds2tf）。
   素性は g2 の素性＋追加の素性＋3連単 q̂ を集計した q̂2。2連単オッズの揃った月が2か月以上前にある月だけ厳密。
   無い月は 3連単 q̂ の集計（AGG）で埋める。
4. **g2+ も厳密版だけで作る**（`g2wf --q2 agg|direct`）。厳密な月 m について、m より前の当たった2連単
   （学習行の q̂2 も上のウォークフォワード版）で学習し、m を予測。
5. `nirensho_today.py` も同じ作り（当日の月より前の揃ったオッズ月すべてで q̂、2連単オッズが2か月以上あれば q̂2 を直接）。

制約: 着順モデル P の OOS 予測は 2024-05 からしか無い（`pred/pred_*.npz`）。q̂ の素性に P を使うので、
**2023-11〜2024-04 のオッズは今の作りでは使えない**。使うなら P を 2023-11 まで遡って作る必要がある（別の作業）。
g2+ は 2024-05 からの当たりで学習し、評価は 2024-11（`EVAL_FIRST_MONTH`）から。

## 事前に決めた候補（6本）

全部「2連単30通りのうち、確率 P2（3段モデルの集計）≥ 下限の目について EV = P2 × g2+/100」で選ぶ。欠場艇を含む目は返還、
2連単の払戻が無いレースは買わない。1点100円。

| 名前 | q̂2 | 買い方 | P2 下限 | EV 下限 | 入れた理由 |
|---|---|---|---|---|---|
| C1 | 3連単 q̂ の集計 | EV最大1点 | 0.05 | 1.1 | C2 の閾値の感度 |
| **C2（主仮説）** | 3連単 q̂ の集計 | EV最大1点 | 0.05 | 1.2 | 前回の候補そのもの |
| C3 | 3連単 q̂ の集計 | EV最大1点 | 0.05 | 1.3 | C2 の閾値の感度 |
| C4 | 3連単 q̂ の集計 | EV最大1点 | 0.10 | 1.2 | 確率の高い目に絞ると月の的中数が増えにくい代わりに配当のばらつきが減る。勝ち月数の基準に効くかを見る |
| C5 | 3連単 q̂ の集計 | EV≥下限の全部 | 0.10 | 1.1 | 前回の厳密版で一番良かった2連単（1.060 勝6/10） |
| C6 | 2連単オッズで直接 | EV最大1点 | 0.05 | 1.2 | AGG の近似（3連単の市場確率の和 ≠ 2連単の市場確率）を外す。2連単オッズが揃ったときだけ評価 |

- レース種別・場などの絞りは入れない（入れる理由が今は無い）。
- 試した数: これで 6（2連単の複数点買いの累計は 184＋単勝併用 6＋この 6）。コードは `multi_bet_eval.V2_CANDIDATES`。

## 期間の切り方と判定（評価の前に固定）

- 評価に使うのは「厳密な月」（q̂ はその月より前のオッズだけ、g2+ はその月より前の当たりだけ）で、暦月が揃った月だけ。
- **検証用 = 厳密な月のうち新しい 12 か月**（rules.yaml `adopt_window_months`）。**発見用 = それより前の厳密な月すべて**。
  - 例: 3連単オッズが 2024-05 から揃えば、厳密な月は 2024-07〜（g2+ の都合で評価は 2024-11〜）2026-10。
    発見用 2024-11〜2025-10（12か月）、検証用 2025-11〜2026-10（12か月）。
- **発見用の厳密な月が 6 か月未満なら判定しない**（動作確認だけ）。
- 選び方: 発見用で的中 100 本以上の候補のうち、発見用の通算回収率が最良の1本を選び、その1本だけを検証用で判定する。
  主仮説 C2 は選ばれなくても並べて出す（判定の根拠は「選ばれた1本」）。
- 合格ライン（rules.yaml `evaluation`）: 検証用 12 か月で通算回収率 > 1.0、かつ勝ち月 ≥ 8。日単位のブートストラップの 90% 区間も併記。
- 合格しても**本番の選定には入れない**。`notes/decisions.md` に条件・買い方・点数を日付つきで登録し、
  その日より後の月だけで前向き（紙上）に記録する。rules.yaml は触らない。

### 正直に書いておくこと（偶然の当たりの扱い）

- 検証用 2025-11〜2026-10 は、同じ候補を前回すでに見ている（厳密版 2026-01〜10 で 1.011、LOMO 版で 1.173）。
  今回の検証用は「前に見た月の、厳密版での見直し」であって、まっさらな検証ではない。
- 発見用（2024-11〜2025-10）も、同じ C2 を LOMO 版の q̂ で 1.108・勝ち月 7/12 と出している。厳密版の q̂ は新しいが、P と払戻は同じ。
- だから v2 の結果で言えるのは「厳密な q̂ にしても損益分岐を明らかに超えるか／超えないか」まで。採用の証拠は前向きの記録だけ。

## 再実行の手順

```
W=scripts/analysis/multi_bet.py
python $W coverage                 # 揃った月の確認（新しい月が 95% を超えたか）
python $W prep                     # 揃った月を mb/odds_months.json に書き、オッズを読み直す（約2分）
python $W oddswf                   # q̂ の学習（学習月の組ごとに1回。1回 2〜4分、2スレッド）。--months で分けて回せる
python $W odds2wf                  # 2連単オッズが2か月以上揃っていれば（無ければ何もしない）
python $W g2wf --q2 agg            # 厳密な月の g2+（1か月約10秒）
python $W g2wf --q2 direct         # odds2wf をした場合
python $W v2eval                   # 候補6本の評価 → mb/v2_report.md（発見用が6か月未満なら判定しない）
```

- 古いオッズの月が増えると、全部の月の学習月（拡大窓）が変わるので `oddswf` はほぼ全部作り直しになる（月数 ≒ 学習回数）。
  バックグラウンドは2時間で切れるので、`--months` で半分ずつ回す。
- 作業ファイルは trifecta の workdir の `mb/`。2026-11-03 時点の旧版の結果は `mb_v2/` に退避済み。
