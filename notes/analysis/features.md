# 特徴量テーブル（scripts/features.py）

前夜（番組表が出た時点）に手に入る情報だけで作った、1艇1行の特徴量テーブル。モデルとバックテストの入力にする。

- 作り方: `python scripts/features.py --from 20251101 --to 20261031 --out <path>.parquet`（1年・33.7万行で約1分）
- 関数: `build_features(con, hd_from, hd_to, stats_lag_days=0) -> DataFrame`（`con` は読み取り専用で開いた SQLite 接続）
- リーク検査: `python scripts/features.py --db <DB> --workdir <作業dir> --leak-check 20251101,20260324`
- 単変量レポート: `python scripts/features.py --report <path>.parquet`
- 出力は 1行=1艇（hd, jcd, rno, lane が主キー）。特徴量177列、ID 7列、ラベル7列（`y_` で始まる列）
- 大きいファイルはリポジトリに置かない（`data/features/` は gitignore されていない）。2025-11〜2026-10 版は約130MB。

## 使えるタイミングの約束

| 元データ | 使った範囲 | 理由 |
|---|---|---|
| entries（番組表） | レース日当日の行（＋モーター入れ替え検出に当日以前の行） | 前夜に出る |
| racer_stats（期別成績） | 算出期間の最終日 hd ＋ lag ＜ レース日 の最新行 | CLAUDE.md の表どおり。lag は既定0（下の注意を参照） |
| results（成績） | レース日より**前の日**だけ | 当日の前半レースの結果も使わない（前夜に作る前提） |
| results の展示タイム・進入・ST | 過去日の分だけ（選手・モーターの履歴として） | 当日分は使わない |
| races（天候・風・波）, beforeinfo, odds | 使っていない | 当日・直前・締切の情報 |
| payouts | ラベル `y_tansho_payout` だけ | 特徴量には使わない |

`y_` で始まる列（y_pos, y_win, y_top2, y_top3, y_course, y_tansho_payout, y_has_result）は当日の結果。**特徴量に入れてはいけない**。`y_has_result=False` は成績が無いレース（中止・取り込み漏れ・下記の唐津問題）。

## 特徴量一覧

「窓」はレース日 d に対して [d−N日, d−1日]。率の分母は「出走した回数」（着順か ST がある行）。

### 1. 番組表（entries.data）— 前夜
| 名前 | 意味・計算 |
|---|---|
| grade | 級別 A1=4, A2=3, B1=2, B2=1 |
| national_win_rate, national_2ren_rate | 全国勝率・2連率 |
| local_win_rate, local_2ren_rate | 当地勝率・2連率（0 は「当地実績なし」とみなして NaN） |
| local_win_rate_missing | 当地実績なしフラグ |
| local_minus_national | 当地勝率 − 全国勝率 |
| motor_2ren_rate, boat_2ren_rate | モーター/ボート2連率（番組表の値） |
| age, weight | 年齢・体重 |
| has_hayami | 早見あり（その日もう1走ある＝好調/人気選手の目安） |
| distance, close_hour | 距離、締切時刻の時（ナイター判定に） |
| r_fixed_course, r_final, r_semifinal, r_special, r_qualify | レース名から: 進入固定・優勝戦・準優・選抜/特選/ドリーム等・予選 |
| ser_n, ser_avg_pos, ser_win, ser_top3, ser_last_pos | 今節成績（series_results）の走数・平均着順・1着率・3着内率・直前走の着順 |

| 名前 | 意味・計算 |
|---|---|
| rs_win_rate, rs_top2_rate, rs_avg_st, rs_ability, rs_ability_prev | 期の勝率・2連率・平均ST・能力指数（今期/前期）。出走0なら NaN |
| rs_starts, rs_first_count, rs_second_count, rs_final_count, rs_champion_count, rs_training_term | 出走数・1着数・2着数・優出数・優勝数・登録期 |
| rs_grade, rs_grade_prev1 | 期の級別・前期級別 |
| rs_age_days | 使った期別成績の古さ（レース日 − 算出期間最終日） |
| rs_c_starts, rs_c_win, rs_c_top2, rs_c_top3 | そのコースの進入回数・1着率・2連率・3連率（pos1〜3 / starts から計算） |

| rs_c_win_shrunk | rs_c_win を場×枠の基礎1着率（vl365_win）へ縮小: (1着数 + 10×基礎) / (進入数 + 10) |
| rs_course_share | 期の全進入のうちそのコースの割合 |
| rs_F, rs_L, rs_K | 期の F・L（選手責任）・K（選手責任欠場）回数（全コース合計） |

### 3. 選手の直近成績（results, レース日より前）
| 名前 | 意味・計算 |
|---|---|
| r{30,90,180}_n | 窓内の出走数 |
| r{N}_win, _top2, _top3 | 1着率・2連対率・3着内率 |
| r{N}_avg_pos | 平均着順（完走のみ） |
| r{N}_acc | 事故率（ST はあるが着順なし＝F/転覆/失格など） |
| r{N}_avg_st, r{N}_st_sd | 平均ST・STのばらつき |
| r{N}_st_rank | レース内のST順位の平均（1=最速） |
| r{N}_ex_res | 展示タイム − そのレースの展示平均（負が速い）の平均。選手＋乗ったモーターの足の目安 |
| days_since_last_race | 前走からの日数 |
| rc_n, rc_win, rc_top2, rc_top3, rc_avg_st, rc_st_rank | 365日、**実際の進入コース（entrance_position）＝この艇の枠番**のときの成績 |
| rc_win_shrunk | rc_win を場×枠の基礎1着率へ縮小（k=10） |
| rl_n, rl_win, rl_top3 | 365日、同じ場（当地）の成績 |

### 4. モーター（results, レース日より前・同じ入れ替え期だけ）
キーは (場, 入れ替え期, motor_no)。
| 名前 | 意味・計算 |
|---|---|
| m_n | 今期このモーターの出走数 |
| m_win, m_top2, m_top3 | 今期の1着率・2連対率・3着内率（自前集計） |
| m_res3, m_res1 | **選手の腕と枠を差し引いた**上振れ: 各走の (3着内 − 期待3着内率) の平均。期待値は「枠番×その時点の選手期別勝率(0.5刻み)」の過去365日実績（その走の日より前だけ、事前分布つき） |
| m_ex_res | 今期の展示タイム − レース展示平均 の平均（負が速い） |
| m_res3_shrunk, m_ex_res_shrunk | 上の合計 / (n + 20)。出走が少ないうちは 0 に寄せた版。モデルにはこちら推奨 |
| motor_epoch_days | 今期のモーターが入ってからの日数（不明なら NaN） |

**モーター入れ替えの検出**: 番組表の `motor_2ren_rate` は入れ替え直後に全機 0 にリセットされる。場ごと・日ごとに「motor_2ren_rate==0 の割合」を出し、**8割以上になった最初の日**（前の観測日は8割未満）を入れ替え日とする。2節目にまだ半分くらい 0 が残る誤検出を消すため、入れ替え日どうしは180日以上空ける。番組表のある 2023-05〜2026-11 で全24場とも年1回ずつ（計76回）検出できた（例: 桐生 2023-12-28 / 2024-12-31 / 2025-12-27、住之江 2024-03-15 / 2025-03-15 / 2026-03-23、大村 2024-06-19 / 2025-06-22 / 2026-05-24）。
検出に使うのはその日以前の番組表だけなので、前夜に分かる情報で閉じている。保険としてモーター期は最長400日で打ち切る。最初の期（番組表の開始 2023-05 より前に入ったモーター）は開始日が分からないので `motor_epoch_days` は NaN。

### 5. 場×枠の基礎確率・レース内の相対値
| 名前 | 意味・計算 |
|---|---|
| vl{60,365}_win, _top2, _top3 | その場・その枠番の直近60/365日の1着率・2連率・3連率 |
| v_lane1_win60 | その場の1号艇1着率（直近60日）。水面の荒れ・季節風の代理 |
| {f}__rank | レース内で f が大きい順の順位（1=最大。ST のように小さいほど良いものも「大きい順」なので注意） |
| {f}__dmean | f − レース内平均 |
| {f}__dmax_other | f − 自分以外の最大値（+ なら自分がトップ） |
| {f}__dlane1 | f − 1号艇の値 |
| national_win_rate__share, rs_win_rate__share | 勝率のレース内シェア |
| race_n_a1, race_n_boats | レース内の A1 数・艇数 |

相対値を作った f: national_win_rate, rs_win_rate, rs_ability, motor_2ren_rate, m_res3_shrunk, m_ex_res_shrunk, r90_top3, r90_win, r90_avg_st, rc_win_shrunk, rs_c_win_shrunk, rs_c_avg_st, rs_c_avg_start_rank, local_win_rate, grade。

## リーク対策と検査結果

対策:
- 履歴は「合成キー×日」で並べた累積和の差で窓集計し、上限を「レース日の0時」（その日を含まない）で切る（`_Hist.query`）。当日の前半レースも入らない。
- 期別成績は `merge_asof(..., allow_exact_matches=False)` で「算出期間最終日 + lag < レース日」の最新行だけ。
- モーター入れ替え検出・唐津補正（下記）も、レース日以前の番組表だけを使う。
- 累積和は 1e-6 単位の整数に丸めて足す（float の誤差で読み込み期間によって値が揺れないように）。

検査（`leak_check`）: DB のスナップショットから、日 D について
1. **切り詰めDB**: entries は D 以前、results・payouts・racer_stats は D より前だけを入れた別DBを作り、そこから作った D の特徴量が、全データDBから作ったものと全列一致するか
2. **期間まとめ作り**: 期間 [最初の検査日, 最後の検査日] をまとめて作ったときの D の行と、D だけ作ったときが一致するか（後ろの日のデータが混ざらないか）

## 気づいた注意点

1. **唐津(23)の成績が津(09)として入っている（取り込みバグ）**。results / payouts / races に jcd='23' が1行もなく、jcd='09' に両場分が混ざっている。主キーが (hd, jcd, rno, lane) なので、**両場が同じ日に開催した日（327日）は唐津の成績が津に上書きされて全部消えている**（重なった日は全部津が残っていた）。唐津が残っているのは津が開催していない日だけ。
   - features.py では、jcd='09' の各レースの6艇を番組表 09/23 の (hd, rno, lane, 選手) と突き合わせて多数決で場を付け替えている（`venue_fix_map`。jcd='09' の 10,935 レース中 10,923 レースが番組表で判別できた。残り12レースは 09 のまま）。
   - それでも消えた分は戻らない。2025-11〜2026-10 で唐津の `y_has_result` は 49%（津は 96%）。唐津の選手・モーター履歴も半分ほど欠ける。取り込みコードは修正済みで、results/payouts/races を全期間取り込み直す予定（2026-11-02 時点の連絡）。検証・バックテストで唐津と津は要注意（verify.py の的中判定にも影響している可能性）。
   - features.py は特徴量の行を **entries（番組表）の jcd を基準**に作り、ラベルも entries の (hd, jcd, rno, lane) に結合している。results の jcd は履歴集計のキーにしか使わず、そこも上の補正を通す。補正は「09 の行のうち番組表の 23 と選手が合うものだけ 23 に付け替える」なので、取り込み直し後は付け替えが 0 行になり何もしない（そのとき stderr の `[venue-fix]` 行が出なくなる）。
   - **取り込み直し後の再確認**: (1) 特徴量を作り直す、(2) `--leak-check` を同じ日付で再実行、(3) `--report` と条件付きロジットの数字を更新。唐津の y_has_result が 9割台に上がり、唐津の選手・モーター履歴が増えるので、唐津・津の行の値はかなり変わるはず。
2. **期別成績の公開時期**: CLAUDE.md の表では「算出期間の最終日より後なら使える」だが、実際の公開（ファンデータ）は最終日から1か月以上あとで、適用（級別の切り替え）は翌々月。結果の先取りではないので「当たり外れのリーク」ではないが、11/1〜12月上旬・5/1〜6月上旬の前夜には本当はまだ手に入らない。厳密にやるなら `--stats-lag-days 45` 程度で作り直して比べること。
3. 当日の前半レースの結果（同日・同選手の1走目）は使っていない。朝〜日中に買うなら使える情報だが、前夜選定の約束どおり外した。
4. 番組表（entries）は 2024-11〜2025-10 が一部しかない（今も取り込み中）。特徴量の対象行はその期間だと少ない。履歴（results）は 2023-05〜 入りつつあるので、選手・モーターの直近成績は全期間で計算できる。モーター入れ替え検出は番組表頼みだが、その期間も入れ替え日の前後の番組表は入っていて検出できた。
5. `r{N}_acc`（事故率）は F と転覆・失格などを区別できない（results に事故種別が無い）。F の正確な数は期別成績の `rs_F`。
6. モーター上振れの期待値テーブルは「枠×選手勝率」だけ。場の違い・相手の強さは補正していない。改善余地あり。
7. ボートの履歴は作っていない（番組表の boat_2ren_rate のみ）。ボートもモーターと同じ頃に入れ替わる場が多い。
8. `__rank` は大きい順。ST や平均着順のように小さいほど良い指標の rank は「大きいほど悪い」。
9. データは別プロセスが書き込み中なので、同じ日付範囲でも作るたびに少し変わることがある（新しく入った過去の成績が履歴に入るため）。再現したいときは DB のスナップショット（`sqlite3` の backup）から作る。
